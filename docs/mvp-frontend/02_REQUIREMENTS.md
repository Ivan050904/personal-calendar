# Requirements

## Event

Поля:
- id
- calendarId
- title
- description/notes
- start date-time
- end date-time
- timezone
- categoryId (optional)
- color
- recurrenceRuleId (optional)
- createdAt
- updatedAt
- deletedAt (optional)

Событие может быть:
- одноразовым;
- ежедневным;
- еженедельным;
- по выбранным дням недели;
- ежемесячным;
- all-day.

Обычное событие не требует обязательной отметки выполнения.

## Recurrence

Поддерживаются:
- never;
- daily;
- weekly;
- selected weekdays;
- monthly.

Окончание:
- без окончания;
- до определённой даты;
- после N повторений.

Календарь обязан корректно учитывать границу окончания.

## Recurrence exceptions

Для отдельного экземпляра повторяющегося события поддерживаются:
- изменить только этот экземпляр;
- изменить этот и следующие;
- изменить всю серию;
- удалить только этот экземпляр;
- удалить всю серию.

Перетаскивание конкретного экземпляра повторения по умолчанию меняет только этот экземпляр.

Исключения должны храниться отдельно от базового правила повторения.

## Overlap

При пересечении событий приложение предупреждает пользователя, но не запрещает сохранение.

## Plans

Plan — временной блок с названием и чек-листом.

Поля:
- id
- calendarId
- title
- description (optional)
- start
- end
- timezone
- color
- tasks
- createdAt
- updatedAt
- deletedAt

PlanTask:
- id
- planId
- title
- completed
- order

PlanTask не имеет собственного времени в MVP.

На календаре план отображается одним блоком. При открытии/раскрытии виден чек-лист и прогресс.

## Tasks

Задача может быть:
- без даты;
- с датой, но без времени;
- с датой и повторением (ежедневно / еженедельно / ежемесячно) — без времени на шкале.

Поля:
- id
- calendarId
- title
- description (optional)
- dueDate (optional)
- recurrenceRuleId (optional; requires dueDate)
- completed
- createdAt
- updatedAt
- deletedAt

Повторение задачи переиспользует `RecurrenceRule` (те же frequency / interval / weekdays / dayOfMonth / untilDate / occurrenceCount, что у событий). Отдельной recurrence-системы для задач нет.

Поведение завершения (ADR-015):
- обычная задача — toggle `completed`;
- повторяющаяся — при отметке «сделано» `dueDate` сдвигается на следующий экземпляр, `completed` остаётся false; если следующего нет — `completed=true` на последней дате.

На экране Сегодня / в блоке «Сегодня» показываются задачи с `dueDate` = сегодня и незавершённые с `dueDate` раньше сегодня (просроченные).

Задачу с датой можно перемещать на другую дату drag-and-drop.

## Lists

Пользовательские списки:
- название списка;
- элементы списка;
- порядок элементов;
- completed.

Пример: Покупки.

В MVP нет автоматического превращения ListItem в Task.

## Categories

Категория — логическая группировка.

Цвет события хранится отдельно от категории и выбирается при создании/редактировании события.

Можно иметь несколько доступных цветов.

## Reminders

У события может быть несколько напоминаний.

Поддерживаемые интервалы MVP:
- 5 минут;
- 15 минут;
- 30 минут;
- 1 час;
- 1 день.

Browser notifications можно включать/выключать.

## Trash

Удалённые сущности помещаются в корзину.

Срок хранения — 30 дней, после чего объект может быть окончательно удалён.

Возможность восстановления.

## Search

Поиск по:
- событиям;
- планам;
- задачам;
- спискам.

## Filters

Фильтрация календаря по категориям/релевантным признакам.

## Calendar interaction

Day/Week:
- временная шкала;
- события блоками;
- drag event → изменение времени;
- resize → изменение длительности;
- drag на другой день → изменение даты.

Click/tap по времени открывает форму создания с предзаполненной датой и приблизительным временем. Пользователь может изменить время.

## Month

Обычная месячная сетка. Конкретная визуальная детализация может быть уточнена в UI/UX, но не должна нарушать общую модель.

## Backup

Настройки:
- экспорт данных;
- импорт данных.

Экспорт должен включать календарь, события, recurrence rules/exceptions, планы, plan tasks, задачи, списки, категории, reminders и необходимые настройки.

## Timezone

Дата-время, зависящее от времени, хранится с timezone. В MVP по умолчанию используется timezone устройства; архитектура допускает ручное изменение timezone в настройках.

## Theme

Поддерживаются:
- светлая тема;
- тёмная тема.

Переключение пользователем.
