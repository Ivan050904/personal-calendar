Сначала прочитай:
- README.md

## Миссия
Реализуй весь roadmap от первой незавершённой волны до Wave 15 в рамках одного запуска.

**Не останавливайся после каждой волны, чтобы спросить «что дальше?».** Если следующая волна определена roadmap — переходи к ней автоматически.

После каждой волны обязательно проходи Quality Gate.

## Обязательные правила

### Existing frontend
Сначала изучи реальный проект. Не выдумывай стек. Не переписывай работающие части без необходимости.

### Backend
Используй:
Python + FastAPI + Pydantic v2 + SQLAlchemy 2.x + Alembic + MySQL 8.x + pytest + HTTPX + Uvicorn.

**Docker не использовать в MVP.**

### AI
AI не имеет SQL/repository/DB credentials. Только structured proposals. Backend валидирует. Mutation только после explicit confirmation.

### Update/Delete
Используй TargetSelector. При нескольких кандидатах требуй выбор. Для recurring — scope.

### Secrets
API key только в backend environment `.env`. Никогда не печатай и не коммить. Если ключ уже есть локально — используй, не раскрывая.

### Tests
Не удаляй и не ослабляй тесты. После каждой волны:
targeted tests → regression → typecheck → lint → build → исправление → повторная проверка.

### No fake completion
Не называй функцию готовой без реально выполненных проверок.

## Алгоритм каждой волны
1. Прочитать requirements.
2. Проверить фактический код.
3. Реализовать.
4. Запустить targeted tests.
5. Запустить regression.
6. Typecheck.
7. Lint.
8. Build.
9. Исправить ошибки.
10. Повторить проверки.
11. Обновить CURRENT_TASK.
12. Обновить CHANGELOG.
13. Отметить wave complete.
14. Сразу перейти к следующей.

## Если волна уже выполнена
Проверь код и тесты. Не переписывай ради вкуса. Иди дальше.

## Если реальный API key доступен
В финальной E2E-волне выполни хотя бы один реальный smoke test. Не записывай ключ в код/репозиторий.

## Если ключа нет
Используй mocks там, где это разрешено, а реальный smoke test отметь как ожидающий локальный ключ. Не притворяйся, что реальный тест выполнен.

## Если Whisper
Проведи реальный smoke test при возможности и выбери модель после benchmark, а не наугад.

## Остановка
Остановись только при настоящем блокере:
- конфликт требований;
- риск потери данных;
- невозможно безопасно продолжить без отсутствующего бизнес-решения;
- критический тест не удаётся исправить;
- обязательная зависимость недоступна.

Не останавливайся просто потому, что закончилась одна волна.

## После Wave 15
Сделай финальный audit всех требований и выдай:
- завершённые волны;
- команды/тесты;
- результаты real AI/Whisper smoke tests;
- известные ограничения;
- точные команды запуска;
- состояние миграций;
- проверку секретов.

Затем STOP.
